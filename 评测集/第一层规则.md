# 第一层规则清单 v1.0（初始基线）

> 负责人：算法组｜对应看板：第一阶段「写出第一层规则清单」
>
> 状态：**规则标准已确定，尚未在真实合同上测试**。后续依据实测误报、漏报迭代。
>
> 范围：可提取文本的单份重疾险合同；第一层定位与提示，不做疾病定义的实质偏离判定、法律效力判断或理赔结论。

## 一、制定依据

这套规则不是一份现成的行业标准，而是项目基于**规范要求 + 保险信息抽取研究 + 真实合同常见表达**制定的初始识别基线。

1. **《中华人民共和国保险法》第16—18条**：如实告知、免责条款提示说明、保险责任与责任免除等，为优先关注的合同要素提供法律依据。
2. **《重大疾病保险的疾病定义使用规范（2020年修订版）》第1节和第2.1条**规定，定名为重大疾病保险且保险期间主要覆盖成年人（十八周岁及以上）的产品，应包含六种核心重度疾病。若产品还保障保额低于上述六种重度疾病的其他疾病，还应包含三种轻度疾病。判断适用性时须核对产品类型和合同采用的规范版本。
3. **Sun 等，NAACL 2019，TOI-CNN / ETIP**：将保险合同信息抽取划分为保障内容、保障期间、给付条件、等待期、保险金额、责任免除、终止等类别。这支持“先抽要素、再理解”的方法；本文的词表和具体正则为项目自拟，须经测试验证。

## 二、规则执行的统一标准

**基础流程：** 合同文本解析成功 → 按章节与条款切分 → 关键词／模式发现候选 → 根据所在条款判断语义 → 取回原句 → 生成候选批注或索引记录。

**命中标准：** 不能仅凭一个词出现就生成高风险批注。至少能确定（1）命中目标是什么；（2）属于哪一条款／章节；（3）对应哪一段原文。抽取失败标为“未核实”，不得写“合同没有”。

**复核标准：** 遇到否定、例外、跨页缺失、目录项、句中条号引用、规范版本不明等情况，先保留候选并标记需复核；不自动解释为免责违法或必定不赔。

**统一输出：** 前端仍使用 `clauseId / quote / plain / riskLevel / riskReason / visibility / benchmark / layer / confidence / needsReview` 十个既有字段，不新增共享字段。规则编号、命中位置等只作为内部实现记录。

## 三、基础识别规则（首版固定）

| 编号 | 识别对象 | 初始触发方式 | 必要排除与限制 |
|---|---|---|---|
| L1-01 | 保险责任章节 | 独立标题出现“保险责任”“保障责任”等 | “详见保险责任”不是标题；目录要去重 |
| L1-02 | 责任免除章节 | 独立标题出现“责任免除”“除外责任”等 | 同上；不能仅凭是否在该章节判断法律效力 |
| L1-03 | 等待期 | “等待期”及其时长、起算或等待期内处理条款 | 不推断未写出的天数；多个等待期分别记录 |
| L1-04 | 健康告知／如实告知 | “健康告知”“如实告知”“如实回答”等，结合条款标题 | 仅抽到告知义务，不代表已获得完整投保问卷 |
| L1-05 | 全部满足条件（AND） | “须同时满足”“均须满足”“全部满足”等 | 需找到所连接的完整条件，不能只记关键词 |
| L1-06 | 至少一项条件（OR） | “条件之一”“至少一项”“任一项”等 | 不得误写为全部满足；条件不完整时需复核 |
| L1-07 | 时间持续条件 | “持续／连续／累计／不少于”与“×日／月／年”等，且涉及病情／治疗／状态 | 排除保费缴纳年限、保险期间等非疾病持续条件 |
| L1-08 | 手术／治疗条件 | “须／必须／已实施”与手术、移植、透析、治疗等关联 | “无需手术”、仅列举示例及可选方案不视为强制条件 |
| L1-09 | 犹豫期 | “犹豫期”及其天数、起算、退保处理 | 只抽合同原文，不默认所有产品天数相同 |
| L1-10 | 现金价值 | “现金价值”“退保金”及计算、附表所在条款 | 不根据不完整表格计算金额；可只定位条款 |
| L1-11 | 六种核心重度疾病 | 用2020版规范的官方病种名称词典逐项匹配 | 先核实合同版本、适用对象；仅判断名称是否检出 |
| L1-12 | 三种核心轻度疾病 | 用2020版规范的官方病种名称词典逐项匹配 | 先核实是否触发轻度疾病覆盖要求；不机械判违规 |

**六种核心重度：** 恶性肿瘤——重度；较重急性心肌梗死；严重脑中风后遗症；重大器官移植术或造血干细胞移植术；冠状动脉搭桥术（或称冠状动脉旁路移植术）；严重慢性肾衰竭。

**三种核心轻度：** 恶性肿瘤——轻度；较轻急性心肌梗死；轻度脑中风后遗症。

名称识别可以维护经人工核对的别名表，但**不得凭别名自行认定定义等价**。对2007版旧合同、少儿产品、团体产品先记录适用性；适用性不明时仅做原文定位。

## 四、隐性限制：三类种子规则

这三类来源于项目整理的公开保险纠纷案例，只用于**发现需要关注的合同限制候选**，不是普遍有效的违法判定公式。案例出处见[整合方案第12节「司法依据」](../docs/md文档/重疾险条款风险批注工具-整合方案.md#司法依据)。

| 编号 | 初始候选特征 | 必须核对的上下文 |
|---|---|---|
| S01 | 首次确诊重大疾病，与“仅／只按累计已交保费给付”等同时出现 | 是否属于等待期退费、退保或真正的重疾保险金责任；不擅自计算降幅 |
| S02 | 严重Ⅰ型糖尿病的定义中，还要求特定并发症、植入起搏器、切除脚趾等 | 取出完整定义和“同时／至少一项”关系，不直接认定医学不合理 |
| S03 | 慢性胰腺炎等定义中，额外关联严重糖尿病、营养不良、持续胰岛素治疗等 | 确定是必需条件而非举例或可选条件；保留具体持续时间 |

标题位置用于判定**可见性**，例如限制写在保险责任正文或疾病释义中，应优先提醒用户关注；这不等于系统认定条款无效。

## 五、最小测试与迭代标准

**本轮先定规则，不预先宣称准确率。** 产品选定的3份开发合同用于初测与修正；至少2份未用于调整规则的合同用于独立复核。每条规则都记录人工标注的应命中原句、系统命中原句和错误原因。

首轮实测至少检查：

1. 标题识别能否排除目录和条文引用。
2. 等待期与持续治疗时间是否混淆。
3. “同时满足／满足其一”的逻辑有没有读反。
4. 手术必要条件有没有把“无需手术”当成“必须手术”。
5. 三类隐性限制是否能定位原句，是否产生明显误报。
6. 疾病名称检索是否因旧版用词、少儿／团体合同导致误判。

评测分别报告**基础要素识别**与**隐性限制候选识别**的正确命中、误报、漏报，计算 `Recall=TP/(TP+FN)`、`Precision=TP/(TP+FP)`；不把标题和风险候选混在一起计算一个漂亮的总分。按照中期报告，开发集第一层召回率目标100%，独立测试集召回率目标不低于90%、精准率目标不低于85%，正式展示批注的原文定位有效率目标100%；均为**待检验目标**。

**迭代原则：** 首轮只修复实际出现的漏检／误报，记录规则版本和对应合同；不为了覆盖所有可能表达而无限扩充词典或加入模型。工程需要的正则表达式在真实文本上验证后再固化。
