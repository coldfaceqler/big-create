# 重疾险条款风险批注工具

用户上传一份重疾险合同，系统给出按风险排序的批注：原文、白话、风险说明，并能点回合同原句。不判断值不值得买，也不判断赔不赔。

仓库里现在是文档，网页还没开始写。先读文档，再领任务。

## 先看这三份

按这个顺序读，不要从别的文件开始。

1. [产品说明](docs/md文档/重疾险条款风险批注工具-整合方案.md)：做什么、做到哪一步算完成。
2. [分工手册](docs/md文档/三人分工与并行工作手册.md)：工程、产品、算法各交什么。
3. [合作操作方法](docs/md文档/小组合作操作方法.md)：怎么克隆、开分支、合并。

## 现在只做第一阶段

上传 PDF，扫描件或解析失败必须显示失败。像重疾险合同的，输出第一层批注和条款索引，点一条能看到原句。另外列出不超过五条「需要你核实的事项」。

这一阶段不做问答，不做两份合同对比，不做理赔材料清单。

| 角色 | 这一阶段交什么 |
|------|----------------|
| 工程 | 网页和解析。失败不能显示成分析完成 |
| 产品 | 白话三截、风险句、禁语、三份合同的理想批注 |
| 算法 | 条款切分错例、可粘贴的规则、第一层召回 |

白话固定成三截：合同写的情形 → 合同还要求什么 → 合同写明的给付。不写「因此能赔」或「因此不能赔」。

## 拿到仓库后

```powershell
git clone https://github.com/coldfaceqler/big-create.git
cd big-create
```

然后：

1. 从最新的 `main` 开自己的分支，名字用 `p1/这件事`。
2. 一个人同一时间只做一件事。做完用 Pull Request 合并，不要直接推 `main`。
3. 模型密钥只放在工程的电脑上。未脱敏的合同 PDF 不要提交。

具体命令、冲突怎么处理、周五对什么，都在[合作操作方法](docs/md文档/小组合作操作方法.md)里。
