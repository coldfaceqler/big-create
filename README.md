# DYOLL：结合大语言模型的保险合同分析软件

用户上传一份重疾险合同，系统给出按风险排序的批注：原文、白话、风险说明，并能点回合同原句。不判断值不值得买，也不判断赔不赔。

项目已加入 Vue 3 + Vite 的中期前端演示。页面使用虚构、预设的样例数据，尚未接入 PDF 解析和真实风险分析。项目范围仍以下面的三份文档为准。

## 中期前端演示

Windows 下可双击项目根目录的「启动演示.cmd」，浏览器会自动打开。保留启动窗口；演示结束后按 Ctrl+C 停止。

手动运行：首次执行 `npm install`，然后执行 `npm run dev`，打开终端显示的本地地址。生产构建：`npm run build`。

直接点击「打开示例合同」即可演示批注阅读、筛选、搜索、条款索引和原文高亮。首页「演示其他处理情况」提供扫描件失败、解析失败和材料性质提醒。选择真实文件只做本地格式检查，不会上传，也不会生成分析结果。

详细启动方式、演示顺序与后续对接说明见 [中期前端演示说明](docs/md文档/中期前端演示说明.md)。

中期 PPT 可使用这两张高清 PNG：[完整首页](docs/screenshots/01-dyoll-home.png)（3795 × 3258）和 [批注与原文](docs/screenshots/02-dyoll-reader.png)（3795 × 2985）。图片展示的是当前前端样例界面。

## 三份文档

1. [产品说明](docs/md文档/重疾险条款风险批注工具-整合方案.md)：做什么、第一阶段做到哪算完成。
2. [分工手册](docs/md文档/三人分工与并行工作手册.md)：工程、产品、算法各交什么。
3. [任务看板](docs/md文档/任务看板.md)：现在能做的每一行。群里说了但没写进看板的，不算排了期。

把 [合作操作方法](docs/md文档/小组合作操作方法.md) 交给你自己的 AI。它会按这个顺序带你：先看群里队友的新消息，再看任务看板，做完把固定格式的进度发回群里。

## 现在只做第一阶段

上传 PDF。扫描件或解析失败必须显示失败。像重疾险合同的，输出第一层批注和条款索引，点一条能看到原句。另列不超过五条「需要你核实的事项」。

不做问答，不做两份合同对比，不做理赔材料清单。

| 角色 | 看板里先做的事 |
|------|----------------|
| 产品 | 三份脱敏条款清单、性质提醒用语 |
| 算法 | 第一层规则清单 |
| 工程 | 上传失败不得显示成分析完成 |

白话是三截：合同写的情形 → 合同还要求什么 → 合同写明的给付。不写「因此能赔」或「因此不能赔」。
